All demos below are live, deployed pages — not screenshots or embeds. Every one
needs a **WebGPU browser** (Chrome/Edge stable, Safari 26+, Firefox rolling out);
see [Introduction](../getting-started/introduction.mdx#browser-support) if a demo
shows a "needs WebGPU" banner instead of running.

### [Hello world](https://pmndrs.github.io/denoiser/hello-world/)
The 10-line story: a noisy render → `Denoiser.create()` → `denoise()` → canvas. No
three.js, no build tricks — the page shows the exact source next to the result.
Start here. Walkthrough: [Quick start](../getting-started/quick-start.mdx).

### [Gallery](https://pmndrs.github.io/denoiser/gallery/)
The flagship quality demo. Pre-rendered path-traced scenes at 1–16 samples per pixel
(plus aux buffers and a converged reference), denoised live in the browser: drag the
before/after divider (there is no camera to orbit), step the noise ladder, toggle
albedo+normal guidance on the same frame. For an interactive scene, use the
[three.js path tracer demo](https://pmndrs.github.io/denoiser/three-pathtracer-webgpu/).

### [Aux inputs](https://pmndrs.github.io/denoiser/aux-inputs/)
What the network actually sees. Shows color, albedo, and normal exactly as fed to
the model, alongside examples of the real mistakes that degrade aux quality —
environment-hit normals, alpha-blended normals, HDR albedo clamping. The live
companion to [Models & weights](../getting-started/models-and-weights.mdx#what-aux-buys)
and the aux-inputs guide.

### [webgpu-raw](https://pmndrs.github.io/denoiser/webgpu-raw/)
Proof of engine-neutrality: a single-file WGSL toy path tracer with no framework —
no three.js, no Babylon, no bundler magic — feeding `denoiseTextures` on the same
`GPUDevice`. The reference for integrating a custom engine that isn't three.js.

### [Pipeline Lab](https://pmndrs.github.io/denoiser/pipeline-lab/)
The full offline pipeline in one page: three-gpu-pathtracer renders below the output
size, this library denoises it, and @pmndrs/upscaler (FSR1) scales it back up, all on one
`GPUDevice` through the path tracer's own `setDenoiser` / `setUpscaler` hooks. Every
stage is tweakable, there are four scenes (or drop in your own `.glb`), and a benchmark
times each stage and scores it against a high-sample reference. See
[Benchmarking on your machine](../guides/benchmarking.mdx).

### [three.js path tracer](https://pmndrs.github.io/denoiser/three-pathtracer-webgpu/)
three r186 `WebGPUPathTracer` and this library sharing one `GPUDevice`: progressive
path tracing, denoised live while it accumulates, CPU-copy and zero-copy paths
side by side. See [The GPUDevice](../concepts/the-gpudevice.mdx) for how the shared
device works. `?fsr=1` path-traces and denoises at half resolution, then upscales 2x with
@pmndrs/upscaler's FSR1 (EASU + RCAS).

> [!NOTE]
> The WebGPU path tracer is early-stage upstream work in `three-gpu-pathtracer`
> (main, 0.0.27), pinned to a commit SHA for this demo — expect rough edges.

### [LDraw Eiffel Tower](https://pmndrs.github.io/denoiser/ldraw-eiffel/)
A LEGO Eiffel Tower on a table: fast raster preview while you orbit, path-trace +
denoise the moment the camera comes to rest. Same pinned-pathtracer caveat as above.

### [Benchmark](https://pmndrs.github.io/denoiser/bench/)
The performance harness behind the numbers in [Performance](../concepts/performance.mdx):
cold + warm timings, per-stage stats, and fp16-vs-fp32 PSNR across image sizes —
reproducible in your own browser, on your own hardware.

## Real-time (temporal) denoising

These use the FidelityFX denoisers (`denoiser/ffx`, `denoiser/three`), not OIDN. See
[Which denoiser do I need?](../guides/realtime-temporal-denoising.mdx#which-denoiser-do-i-need)

### [Ray-traced shadows and reflections in a raster app](https://pmndrs.github.io/denoiser/three-temporal/shadows.html)
The "when would I use this?" demo. A furnished room in a normal three.js raster
pipeline, with two effects ray traced at 1 ray per pixel: area-light shadows,
traced against the real scene meshes with three-mesh-bvh's WebGPU BVH, and glossy
SSR. `ffxShadows()` and `ffxReflections()` denoise them every frame. Toggle each
one against what three.js does without ray tracing (a VSM shadow map, env-map-only
reflections) and against a converged reference. Use the light-size slider to see
contact hardening. A live table shows each pass's GPU cost. There's an optional
half-resolution + FSR3 path.

### [Reflections, explained: probe, SSR, ray tracing](https://pmndrs.github.io/denoiser/three-temporal/reflections-hybrid.html)
An explainer for the three ways a real-time renderer finds reflections, and the hybrid that
mixes them: a box-projected reflection probe (captured once, prefiltered with PMREM), three's
SSR, and rays traced against the scene with three-mesh-bvh. A guided tour sets up one situation
per weakness (a mirror, things off screen, moving objects, contact, rough surfaces) and shows two
methods split-screen; a "where reflections come from" view tints every pixel by what answered
it. Every noisy mode takes one sample per pixel, denoised by `ffxReflections()`, with a cost
table and a "which one should I use?" guide.

### [Baked + dynamic shadows: when to split](https://pmndrs.github.io/denoiser/three-temporal/shadows-split.html)
The static / dynamic split engines use for lightmaps, in the browser: the static half of the
shadow baked once into a lightmap (16 rays per texel, cleaned by OIDN) or gathered in a
world-space cache, and 1 ray per pixel against only the moving objects, denoised every frame by
`ffxShadows()`. Explains what the split buys (converged, steady static shadows; rays that only
test moving objects) and costs (bake time, UVs, memory, a light that can't move), with measured
numbers and when to use it. Both denoisers on one page: OIDN at bake time, FFX live.

### [three.js SSR: FidelityFX vs recurrentDenoise](https://pmndrs.github.io/denoiser/three-temporal/)
three's `webgpu_postprocessing_ssr_denoise` example with `ffxReflections()` swapped
in, split-screen against three's own temporal denoiser.

### [FidelityFX denoisers, raw WGSL](https://pmndrs.github.io/denoiser/ffx-denoiser/)
The test bed behind the numbers in [Real-time (temporal) denoising](../guides/realtime-temporal-denoising.mdx#measured-results):
1-sample shadows and reflections, noisy / denoised / reference panels, no three.js.
