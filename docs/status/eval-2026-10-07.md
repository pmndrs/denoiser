# Eval 2026-10-07: every RT model × every runtime vs native OIDN

17 OIDN RT color models (25 scene/model cases: 2 LDR gallery scenes × 8 LDR
models, 1 HDR path tracer dump × 9 HDR models) on native OIDN 2.5.1 (CPU =
ground truth, Metal) and on ORT / HF kernels / hand-written WGSL in fp32 and
fp16, Apple M5 Pro, headless Chrome. Harness: `tools/eval` + `examples/eval`.

## Findings

**Speed (1080p, mean over models, × = slower than native Metal):**

| | small | base | large |
|---|---|---|---|
| native Metal | 14.3 ms | 24.8 ms | 54.2 ms |
| native CPU | 189 (13×) | 331 (13×) | 739 (14×) |
| ORT fp32 / fp16 | 152 (11×) / 105 (7×) | 309 (12×) / 230 (9×) | runs base (see below) |
| kernels fp32 / fp16 | 121 (8×) / 80 (6×) | 199 (8×) / 162 (7×) | 398 (7×) / 465 (9×) |
| WGSL portable fp32 | 62 (4.3×) | 129 (5.2×) | 317 (5.8×) |
| WGSL fp32 (subgroup-matrix, experimental) | 44 (3.0×) | 87 (3.5×) | 229 (4.2×) |
| **WGSL fp16** | **38 (2.6×)** | **78 (3.1×)** | **201 (3.7×)** |

- Every GPU web runtime beats native **CPU** OIDN; WGSL fp16 by 4–5×.
- WGSL fp16 is ~3× from native Metal (MPSGraph + simdgroup matrix hardware);
  the gap widens on the large model (low-res layers).
- Cold start: WGSL loads a model in ~10–140 ms, ORT ~5–30 ms after the first
  (~0.7 s), kernels ~0.8–1.8 s per model (kernel fetch + compile).

**Quality vs native CPU:**

- **kernels and WGSL match native on every model** — fp32 70–84 dB, ≤1 LSB
  (one case 5 LSB, below); fp16 62–77 dB, ≤1–2 LSB.
- **ORT is wrong on all 6-channel (`*_alb`) and dirty-aux 9-channel
  (`*_alb_nrm`) models**: 32–40 dB, up to 120 LSB, costing up to 4.8 dB vs the
  converged reference. That's the >3-channel first-conv bug; the split-graph
  workaround only covers the clean-aux (`calb_cnrm`) models. The `denoiser`
  facade reaches `*_alb` whenever albedo is passed without normal.
- **ORT miscomputes the large topology** (8.9 dB vs native even with the split
  fix). Fixed in 6deb03d: ORT now runs the base model for `*_large` with a
  warning (53 dB vs native large = base-vs-large difference). It used to throw
  (split input name), or return garbage without split artifacts.
- ORT fp16 is the least accurate fp16 (53–59 dB); kernels fp16 is the most
  (75–78 dB, f32 accumulation).
- Open: `eiffel/rt_ldr_calb_cnrm` (base only) is 5 LSB from native on ALL web
  runtimes identically (70.1 dB) — a shared pre/post difference, not a runtime.

**Model choice (vs converged reference, LDR scenes):** base beats small by
0.1–0.4 dB; albedo(+normal) adds up to ~0.4 dB on spheres, ~0.2 dB on eiffel;
differences between aux variants are within 0.3 dB on these scenes.
